# Contributing to JayPVentures Discussions

Thank you for your interest in contributing to the JayPVentures community. This document outlines how to participate constructively in this repository.

---

## What This Repository Is For

`jpv-discussions` is a public community hub for questions, ideas, feedback, and conversation. It is **not** a codebase repository. Contributions here take the form of:

- Opening or participating in GitHub Discussions
- Filing issues for documentation errors, broken links, or repository improvements
- Submitting pull requests for changes to community files (README, templates, guidelines)

---

## Getting Started

1. **Read the [Code of Conduct](CODE_OF_CONDUCT.md).** All participants are expected to follow it.
2. **Search before posting.** Check existing [Discussions](../../discussions) and [Issues](../../issues) to avoid duplicates.
3. **Use the right channel.** Discussions are for open conversation; Issues are for specific, actionable items.

---

## Opening an Issue

Use one of the provided issue templates when filing an issue:

- **Bug Report** — For documentation errors, broken links, or problems with community files
- **Feature Request** — For suggesting improvements to this repository or its templates
- **Question** — For specific questions better suited to a structured issue than a discussion

Provide as much context as possible. Vague or incomplete issues may be closed without action.

---

## Pull Requests

Pull requests to this repository should be limited to:

- Corrections to README, CONTRIBUTING, or CODE_OF_CONDUCT
- Improvements to issue or PR templates
- Updates to workflow configurations or community health files

### PR Guidelines

1. **Fork** the repository and create your branch from `main`.
2. **Keep changes focused.** One logical change per PR.
3. **Describe your change** clearly in the PR description using the provided template.
4. **Link related issues** in the PR description where applicable.
5. PRs will be reviewed by a maintainer. Expect feedback within a reasonable timeframe.

---

## Style Guidelines

When editing Markdown files:

- Use sentence case for headings
- Use hyphens (`-`) for unordered lists
- Trim trailing whitespace
- End files with a single newline

---

## Reporting Security Issues

Do **not** open a public issue for security vulnerabilities. See the [Security Policy](.github/SECURITY.md) for responsible disclosure instructions.

---

## Questions?

Start a [Discussion](../../discussions) in the Q&A category. The maintainers monitor discussions and will respond.
